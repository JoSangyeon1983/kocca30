# 1 용도와 실행

- 팀원에게 공유하는 파일은 [꼭두각시거리 1.0.0.exe](<꼭두각시거리 1.0.0.exe>) 하나임. Windows x64용이며 실행 파일을 열어 사용함.
- HTML, CSS와 JavaScript, 이미지 10개 및 .NET과 WebView2 Fixed Runtime을 EXE 안에 포함함. 별도 설치와 콘텐츠 다운로드 없이 실행하는 구성임.
- 첫 실행 시 `%LOCALAPPDATA%\Cellbig\KkokduPlay`에 내부 파일과 브라우저 캐시를 준비함. 관리자 권한을 요구하지 않는 구성이나 쓰기 가능한 사용자 저장 공간은 필요함.
- 창 제목과 하단 상태 표시줄에 `버전 1.0.0` 표시함. EXE 제품 버전은 `1.0.0`, 파일 버전은 `1.0.0.0`임.

# 2 파일과 정본

| 항목 | 값 |
|---|---|
| 현재 배포 파일 | `꼭두각시거리 1.0.0.exe` |
| 파일 크기 | 373,196,765바이트. 약 373MB 또는 356MiB임. |
| EXE SHA-256 | `2a69331e1184e0e600b4d9c97e530dff725d13fda19136142bfb63ac998a5df4` |
| 구성 | .NET 10.0.9 자체 포함, WebView2 SDK 1.0.4258.31과 Fixed Runtime 155.0.4283.62 x64임. |
| 빌드 도구 | .NET SDK 10.0.301, Release, `win-x64`, 단일 파일 게시함. |

- 내용 수정의 정본은 [스토리보드](<../../../90_작업 공간/스토리보드/덜미 - 나만의 꼭두각시 스토리보드.md>), 재생 화면과 동작은 [기존 HTML 프로젝트](<../../../90_작업 공간/스토리보드/꼭두각시거리/극 진행 보기.html>), 윈도우 호스트는 [WinForms 소스 폴더](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/>)에서 관리함. EXE는 이 입력에서 만든 배포 출력임.
- 사용자 지정 구현을 단일 EXE로 빌드하라는 현재 요청에 한정해 작업 공간의 입력을 패키징함. 스토리보드나 프로토타입의 내용을 새 기획 근거로 채택하거나 승인 상태를 높이지 않음.

# 3 입력과 변환

## 3.1 콘텐츠

- 입력 범위는 기존 HTML 프로젝트의 실행 파일 4개와 동봉 PNG 10개임. 소품과 음향 제외, 대사 90개와 전환 13개 및 전체 이벤트 103개를 유지함.
- 원문 SHA-256은 `9de855fee7ebecf9f899d374aabcd0360af0e276413eba2ffe48f5e9be9ab8a7`임. 스토리보드와 HTML 입력은 이번 빌드에서 수정하지 않음.
- [빌드 결과 JSON](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증/빌드 결과.json>)에 실행 파일과 입력 14개의 해시, 런타임 원본 URL과 CAB 해시 및 SDK를 기록함.

## 3.2 패키징과 재빌드

- Microsoft 공식 [WebView2 다운로드](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)에서 제공한 `155.0.4283.62 x64` Fixed Runtime CAB를 사용함. 런타임 256개 파일과 웹 파일 14개를 ZIP으로 묶어 실행 파일에 내장함. [Fixed Runtime 배포 방식](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution#the-fixed-version-runtime-distribution-mode) 적용함.
- [빌드.py](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/빌드.py>)는 위키 루트에서 실행함. 공식 CAB를 `tmp/꼭두각시거리 실행 파일/WebView2 155 x64.cab`에 놓고 `expand.exe`로 같은 작업 폴더의 `runtime` 아래에 폴더 구조를 유지해 풀어 둠. 별도 NuGet 패키지 복원이 필요할 수 있음.
- 단일 EXE는 [자체 포함 게시](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/)로 생성함. 네이티브 라이브러리와 ZIP은 실행 시 로컬에서 풀어 사용함. 압축 해제 완료 표식이 있는 경우 기존 캐시를 재사용함.
- 공식 다운로드 파일과 빌드 중간 출력 및 독립 실행용 캐시는 Git에서 제외한 `tmp`에 보관함. 소스와 패키지 잠금 파일 및 검증 기록은 윈도우 앱 폴더에 유지함.

```powershell
python '90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/빌드.py'
```

# 4 검증 결과

## 4.1 자동 검사

- 최종 EXE 하나만 별도 빈 폴더에 복사하고 새 캐시로 첫 실행한 뒤 같은 캐시로 재실행함. `DOTNET_ROOT`를 존재하지 않는 경로로 지정하고 다중 설치 탐색을 끈 상태에서 실행함. 실제 사용한 브라우저 프로세스가 EXE에서 푼 Fixed Runtime 경로에 있음을 확인함.
- 첫 실행의 압축 해제와 재실행의 캐시 재사용을 각각 확인함. 웹 입력 14개의 해시, 이미지 로드와 글자별 표시, 긴 대사의 타이핑 중 스크롤, 이전과 장면 이동, 자동 진행 및 대사 90개 전체와 종료 검사 통과함. JavaScript 예외 없음.
- 창 제목과 하단 상태 표시줄의 `1.0.0`을 자동 대조함. EXE 속성의 제품 버전 `1.0.0`과 파일 버전 `1.0.0.0`도 검사 통과함.
- [검증.ps1](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증.ps1>), [첫 실행 결과](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증/첫 실행/실행 검증.json>)와 [재실행 결과](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증/재실행/실행 검증.json>)에 실행 조건과 결과를 보관함.

## 4.2 시각 확인과 한계

- 최종 앱에서 저장한 [첫 대사 화면](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증/첫 실행/윈도우 앱 첫 대사.png>)과 [긴 대사 화면](<../../../90_작업 공간/스토리보드/꼭두각시거리/윈도우 앱/검증/첫 실행/윈도우 앱 긴 대사.png>)을 직접 확인함. 두 파일은 WebView2 내부 화면 캡처이며 윈도우 제목 표시줄을 포함한 화면 캡처는 아님.
- 실제 검증은 Windows 빌드 26200의 x64 환경에서 수행함. .NET SDK와 Evergreen Runtime을 제거한 별도 PC, Windows 10, ARM64 및 32비트 Windows에서는 실행하지 않음.
- 전체 화면 전환, 여러 모니터와 다른 배율 및 회사 PC의 실행 정책은 미검증임. 코드 서명과 사용자 검토는 수행하지 않음. 설치 파일이 아닌 공유용 실행 파일임.
