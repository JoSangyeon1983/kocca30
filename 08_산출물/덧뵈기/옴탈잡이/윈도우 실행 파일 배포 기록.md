# 1 용도와 실행

- [옴탈잡이.exe](<옴탈잡이.exe>) 하나를 복사하여 실행함. Windows x64용이며 별도 콘텐츠 폴더를 동봉할 필요 없음.
- HTML과 CSS 및 JavaScript, 제공 PNG 12개와 .NET 및 WebView2 Fixed Runtime을 내장함. 첫 실행 시 `%LOCALAPPDATA%\Cellbig\OmtalPlay`에 내부 파일을 준비하며 이후 같은 캐시를 재사용함. 쓰기 가능한 사용자 저장 공간은 필요함.
- 창 제목은 `탈놀음 한바탕 - 옴탈잡이`임. `막 올리기`로 시작하고 Space와 Enter 또는 화면의 버튼으로 진행함. 장면 이동과 이전 대사 및 자동 진행을 제공함.
- 대사가 없는 동작 구간에도 빈 대사창의 배경과 테두리를 유지함. 이전 화자의 얼굴과 대사는 가리며 다음 대사에서 다시 표시함. 시작 전과 종료 후에도 같은 창을 유지함.

# 2 파일과 정본

| 항목 | 값 |
|---|---|
| 배포 파일 | `옴탈잡이.exe` |
| 크기 | 376,475,607바이트. 약 376MB 또는 359MiB임. |
| SHA-256 | `20dc4544647503db2830b56b259ba2a5f42217dcd1b434ffd2f54fc041bda481` |
| 구성 | .NET 10.0.9 자체 포함, WebView2 SDK 1.0.4258.31과 Fixed Runtime 155.0.4283.62 x64임. |
| 빌드 | .NET SDK 10.0.301, Release, `win-x64`, 단일 파일 게시함. |

- 내용의 정본은 [스토리보드의 진행](<../../../90_작업 공간/스토리보드/덧뵈기 - 탈놀음 한바탕 스토리보드.md#3-진행>), 재생 화면과 동작은 [HTML 프로젝트](<../../../90_작업 공간/스토리보드/옴탈잡이/극 진행 보기.html>), 실행 호스트는 [윈도우 앱 소스](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/Program.cs>)에서 관리함. EXE는 이 입력에서 만든 배포 출력임.
- 작업 공간의 현재 구현을 EXE로 만들라는 사용자 요청에 한정하여 패키징함. 원문의 초안과 승인 미확인 상태를 유지하며 다른 기획의 근거로 채택하지 않음. 문서 버전을 새로 부여하지 않음.

# 3 입력과 재빌드

- 변환 기준일은 2026-10-22임. 실행 파일 4개와 PNG 12개를 웹 입력으로 포함함. 원문 대사 35개와 장면 전환 30개, 전체 이벤트 65개를 유지함.
- 원문 SHA-256은 `ec0a03db91b88f9f8e53ffe85e5fab656f78ad9c31776d06ed179422f6acd26f`임. 기웃거림은 잘라내지 않은 기본 이미지를 양끝에서 기울이며, 쫓아내기는 꺽쇠 중앙 고정과 옴탈의 좌우 출현 및 완전 숨김을 유지함.
- [빌드 결과](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/빌드 결과.json>)에 입력 16개와 EXE 및 내장 ZIP의 해시, 런타임 원본 URL과 CAB 해시 및 SDK를 기록함. 런타임 256개 파일과 웹 파일 16개를 EXE에 내장함.
- [빌드.py](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/빌드.py>)는 기존 꼭두각시거리 패키징에서 받은 공식 런타임 캐시인 `tmp/꼭두각시거리 실행 파일/runtime/Microsoft.WebView2.FixedVersionRuntime.155.0.4283.62.x64`와 같은 폴더의 `WebView2 155 x64.cab`를 재사용함. 이 캐시가 없는 환경에서는 빌드 결과에 기록된 CAB를 준비하고 같은 위치에 풀어야 함.
- 빌드 중간 출력과 독립 실행용 캐시는 Git에서 제외한 `tmp`에 보관함. 앱 소스의 `bin`과 `obj`도 추적에서 제외함. 재빌드 시 NuGet 패키지 복원이 필요할 수 있으며 완성 EXE의 실행에는 빌드 도구가 필요 없음.

```powershell
python '90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/빌드.py'
```

# 4 검증과 한계

- [검증.ps1](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증.ps1>)에서 최종 EXE 하나만 별도 폴더로 복사하고 새 캐시로 첫 실행한 뒤 재실행함. 존재하지 않는 `DOTNET_ROOT`와 다중 설치 탐색 해제 조건에서 검사함. 실제 브라우저 프로세스가 EXE에서 푼 Fixed Runtime 경로에 있음을 대조함.
- [첫 실행 결과](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/첫 실행/실행 검증.json>)와 [재실행 결과](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/재실행/실행 검증.json>)에서 압축 해제와 캐시 재사용, 입력 16개 해시 및 이미지 로드를 확인함. 글자별 표시와 긴 대사 스크롤, 이전과 6개 장면 이동 및 자동 진행, 대사 35개 전체와 종료 검사 통과함. JavaScript 예외 없음.
- 시작 전과 무대 동작 및 종료 뒤 빈 대사창이 실제 표시되는지 검사함. 양끝 기웃거림의 기본 이미지와 잘라내기 없음, 쫓아내기의 꺽쇠 중앙 고정과 옴탈 좌우 위치 및 완전 숨김을 최종 EXE에서도 대조함.
- 최종 앱의 [빈 대사창](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/첫 실행/윈도우 앱 빈 대사창.png>), [긴 대사](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/첫 실행/윈도우 앱 긴 대사.png>)와 [왼쪽 기웃거림](<../../../90_작업 공간/스토리보드/옴탈잡이/윈도우 앱/검증/첫 실행/윈도우 앱 left 기웃거림.png>) 화면을 직접 확인함. 저장 화면은 WebView2 내부 캡처이며 윈도우 제목 표시줄은 포함하지 않음.
- HTML은 Edge 로컬 실행의 1280 × 960과 390 × 844 조건에서 빈 대사창과 전체 진행 및 기존 동작을 다시 검사함. [브라우저 검증](<../../../90_작업 공간/스토리보드/옴탈잡이/브라우저 검증.json>)에 결과 보관함.
- 실제 EXE 검증은 Windows 빌드 26200의 x64 환경에서 수행함. 다른 PC, Windows 10, ARM64와 32비트 Windows 및 여러 모니터와 다른 배율은 미검증임. 설치된 .NET과 Evergreen Runtime을 제거한 별도 PC에서는 실행하지 않음. 전체 화면 전환과 코드 서명 및 사용자 시각 검토는 수행 전임.
- 기존 구현과 같이 손 동작의 자동 시연이며 실제 모션 입력과 성공 및 실패 판정, 정밀 관절 동작 및 음향은 구현 범위에서 제외함.
