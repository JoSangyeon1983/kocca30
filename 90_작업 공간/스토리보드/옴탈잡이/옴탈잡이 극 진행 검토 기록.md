# 1 목적과 실행

- [극 진행 보기.html](<극 진행 보기.html>)을 브라우저에서 열고 `막 올리기`를 선택함. 별도 서버와 설치 및 인터넷 연결 없이 실행함.
- Windows에서는 [옴탈잡이.exe](<../../../08_산출물/덧뵈기/옴탈잡이/옴탈잡이.exe>) 하나를 복사하여 실행할 수 있음. 입력과 내장 런타임 및 단독 실행 검증은 [배포 기록](<../../../08_산출물/덧뵈기/옴탈잡이/윈도우 실행 파일 배포 기록.md>)에서 확인함.
- [꼭두각시거리 극 진행 보기](<../꼭두각시거리/극 진행 보기.html>)의 무대, 대사와 재생 조작 방식을 옴탈잡이에 적용한 작업 공간 검토용 구현임. 사용자 지시에 따라 정지 이미지의 이동과 흔들기 및 기울임으로 동작을 표현함.
- HTML과 [극 진행.css](<극 진행.css>), [극 진행.js](<극 진행.js>), [극 진행 데이터.js](<극 진행 데이터.js>) 및 `이미지` 폴더를 함께 유지함. 원본 스토리보드와 이미지 파일은 수정하지 않음.

# 2 입력과 변환 범위

## 2.1 스토리보드와 원문 대조

- 입력은 사용자 지정 [덧뵈기 - 탈놀음 한바탕 스토리보드: 진행](<../덧뵈기 - 탈놀음 한바탕 스토리보드.md#3-진행>) 전체임. 문서에 기록된 현재 버전은 1.1.0임. 초안과 승인 미확인 상태를 유지하며 새로운 기획 버전을 부여하지 않음.
- 작업 공간 스토리보드를 이 HTML의 직접 입력으로 사용하라는 현재 요청에 한정하여 변환함. 다른 기획서의 근거로 채택하지 않음. 관련 문서의 대사와 수치를 추가로 가져오지 않음.
- 변환 기준 SHA-256은 `ec0a03db91b88f9f8e53ffe85e5fab656f78ad9c31776d06ed179422f6acd26f`임. 명시된 대사 35개의 화자, 전체 문장과 원문 행 번호를 재생 데이터에 보존함. 대사 교정과 추가 없음.
- 시작, 쫓아내기, 잡아채기, 채검하기, 몰아내기와 마무리의 6개 장면을 구성함. 대사 35개와 이동 및 상태 전환 30개를 합쳐 재생 이벤트 65개로 구성함. 이벤트 수를 원문의 단계 수로 취급하지 않음.

## 2.2 검토용으로 정한 표현

- 실제 모션 인식과 성공 및 실패 판정 대신 손 포인터와 동작의 자동 시연을 사용함. 쫓아내기는 왼쪽, 오른쪽과 왼쪽 순서로 보여 주며 몰아내기는 좌우의 상, 중, 하 6개 출발점을 반복함. 원문의 실제 랜덤 데이터 테이블을 구현한 결과가 아님.
- 원문에 구체 문구가 없는 쫓아내기 성공 및 실패의 랜덤 대사와 무입력 때 장쇠의 행동 유도 대사는 추가하지 않음. 화면의 동작 설명은 무대 전환 안내이며 등장인물의 새 대사가 아님.
- 춤과 팔 휘두르기는 이미지 전체의 이동, 회전과 흔들기로 간략화함. 팔과 다리 관절을 새로 만들거나 자세 이미지를 생성하지 않음. 장쇠는 대사창 얼굴로만 등장함.
- 이동과 시연 이벤트의 길이는 0.25~3초, 자동 대사 진행은 글자 표시 완료 1.4초 뒤로 정한 검토용 재생값임. 원문에 미기재된 게임 제한 시간과 판정 거리 또는 횟수의 확정값이 아님. 종료 퇴장은 표시를 위해 왼쪽으로 배치함.
- 타이머는 이동과 시연 이벤트의 남은 시간만 표시함. 대사 중에는 정지 표시로 바뀌고 수동 진행을 기다림. 타이머 때문에 대사가 생략되거나 다음 단계로 건너뛰지 않음.

# 3 장면별 표현

| 장면 | 적용한 표현 |
|---|---|
| 시작 | 검은 무대에서 꺽쇠 입장과 첫 대사 및 페이드 인. 옴탈이 왼쪽 끝에서 상반신을 기울여 얼굴을 내밀고 완전히 숨은 뒤 오른쪽 끝에서 같은 동작을 1회 수행함. 이후 꺽쇠 대사를 거쳐 옴탈의 기본 전신을 왼쪽에 배치함 |
| 쫓아내기 | 꺽쇠를 중앙에 고정하고 흔들리는 동작을 반복함. 옴탈은 왼쪽에서 사라진 뒤 오른쪽에 나타나며 같은 방식으로 다시 왼쪽에 출현함. 손 포인터와 단계 표시 및 시연 타이머 적용 |
| 잡아채기 | 꺽쇠 오른쪽 퇴장, 모자 테두리의 확대와 축소, 손 포인터 접근, SD 전환과 흔들기 및 엽전 낙하 |
| 채검하기 | 옴탈의 기본 전신 복귀와 꺽쇠 재등장, 얼굴 확대, 좌우 화살표와 손 포인터 및 세 반응 이미지 전환 |
| 몰아내기 | 꺽쇠 중앙 배치와 흔들기, 6개 출발점에서 곡선을 따라 이동하는 옴탈 얼굴 및 명중 효과 |
| 마무리 | 두 인물의 재등장과 흔들기, 옴탈의 기우뚱한 퇴장, 꺽쇠 중앙 복귀와 마지막 문답 및 페이드 아웃 |

- 단계 표시와 타이머, 손 포인터, 모자 테두리 및 명중 효과는 HTML과 CSS 및 SVG로 구현함. 새 PNG는 생성하지 않음.
- 장면 선택과 이전 대사 이동 시 해당 시점의 전신 또는 SD, 얼굴 확대 및 효과 상태를 함께 복원함.

## 3.1 기웃거림 수정

- 사용자 2026-10-22 정정에 따라 화면을 가로질러 이동하던 최초 구현을 수정함. 왼쪽 상반신 내밀기와 숨김, 오른쪽 상반신 내밀기와 숨김 순서를 적용함.
- 기웃거림 동안 일반 무대용 옴탈은 숨김 유지함. 사용자 추가 정정에 따라 양끝 표시는 `옴탈 서 있는 자세.png` 전체를 그대로 사용하며 아래쪽을 가리던 CSS 잘라내기를 제거함. 몸을 화면 밖에 둔 기본 이미지를 기울여 얼굴을 내밀고 화면 경계에서 자연스럽게 가려지도록 함. 새 이미지 생성과 원본 이미지 수정 없음.
- 각 방향은 1.9초 동안 한 번 내밀고 숨는 동작을 재생하며 해당 이벤트는 2.1초로 구성함. 방향 사이 0.5초와 오른쪽 동작 뒤 0.6초의 완전 숨김 구간을 둠. 이 시간과 30도 기울임은 검토용 표현값임.
- 중앙 배회와 양끝 사이의 전신 이동을 제거함. 두 동작이 끝난 뒤 꺽쇠의 대사를 진행하고, 그 다음에 옴탈이 왼쪽으로 정상 등장함.

## 3.2 쫓아내기 출현 방식 수정

- 사용자 추가 정정에 따라 쫓아내기 준비부터 종료까지 꺽쇠의 기준 위치를 화면 중앙인 가로 50%에 고정함. 그림 전체의 흔들기와 기울임만 반복함.
- 옴탈의 출현 위치는 왼쪽 25%와 오른쪽 75%임. 각 방향에서 표시한 뒤 0.5초 동안 완전히 숨기고 반대편에서 다시 표시함. 이 값과 반복 순서는 검토용 시연값임.
- 이 구간의 옴탈은 위치와 불투명도 전환을 즉시 적용함. 한쪽에서 다른 쪽으로 이동하는 보간을 제거하여 중앙을 가로지르는 모습이 나타나지 않도록 함. 다음 잡아채기의 중앙 이동부터 일반 이동 표현을 복원함.

- 입력 12개 각각의 바이트 수와 크기 및 SHA-256은 재생 데이터의 assetInventory에 보존함. 검증 시 같은 파일을 다시 읽어 해시를 대조함.

# 5 대사와 재생 조작

## 5.1 대사 표시

- 사용자 2026-10-22 지시에 따라 대사가 없는 동작 구간에도 대사창의 배경과 테두리를 유지함. 이전 화자의 얼굴과 대사만 가리고 다음 대사에서 다시 표시함. 시작 전과 종료 후에도 빈 창을 유지하며 작은 화면의 창 높이도 동일하게 유지함.
- 기본 글자 속도는 38ms이며 느리게 60ms와 빠르게 20ms를 선택할 수 있음. 같은 대사의 전체 문장을 페이지로 나누지 않고 창 높이를 넘으면 스크롤함.
- 글자가 추가될 때 마지막 줄을 따라감. 위로 스크롤하면 따라가기를 멈추며 `이어지는 대사 보기`를 선택하거나 맨 아래로 돌아오면 재개함.
- 타이핑 중 `모두 표시`, 대사창 클릭 또는 Space 입력은 현재 대사만 완성함. 다음 입력에서 다음 대사나 동작으로 이동함. 대사창 스크롤과 대사 넘김을 구분함.

## 5.2 이동과 화면

- `이전`, `다음`, `자동 진행`, `장면`, `처음부터`와 `전체 화면` 제공함. Space와 Enter 및 오른쪽 화살표로 진행하고 왼쪽 화살표로 이전 대사로 이동함.
- 무대 전환과 자동 시연은 해당 이벤트 시간이 지나면 다음으로 이어짐. 대사는 기본 수동이며 자동 진행을 켜면 완성 후 다음으로 이어짐.
- 작은 화면에서는 대사창을 무대 아래에 배치함. 동작 구간에도 대사창의 자리를 유지하여 조작 버튼 위치가 바뀌지 않도록 함.

# 6 검증과 한계

## 6.1 실행 검사와 직접 확인

- 2026-10-22 Windows의 Edge 155.0.4283.62를 숨겨진 헤드리스 모드로 실행함. 실제 로컬 file URL과 1280 × 960 데스크톱 및 390 × 844 모바일 조건에서 검사함. 실행 시각은 검증 JSON의 verifiedAt에 UTC로 기록함.
- 원문 SHA-256과 대사 35개의 순서, 화자, 전체 문자열 및 원문 행 번호를 재생 데이터와 독립 대조함. 원본 이미지 12개의 해시도 일치함. 최신 수정 후 최종 페이드와 종료까지 이벤트 65개를 모두 통과함.
- 6개 장면 이동과 이전 대사 이동의 상태 복원, 모자 강조와 SD 전환, 이미지 흔들기의 시간 변화, 엽전 10개와 3개 채검 표정, 탈의 6개 출발점과 실제 화면 이동 및 자동 진행을 검사함.
- 글자별 표시와 긴 대사의 타이핑 도중 자동 스크롤, 전체 문장 보존과 위로 읽기 및 마지막 줄 복귀를 검사함. 모바일의 대사창 분리와 스크롤 및 가로 넘침 없음 확인함. JavaScript 실행 예외 없음.
- 대사창 유지 수정 후 같은 전체 검사를 재실행함. 시작 전과 기웃거림 및 종료 뒤에도 창 자체의 표시와 크기를 확인하고 내부 얼굴과 대사만 가려지는지 검사함. 수정한 HTML의 쫓아내기 화면과 모바일 기웃거림 화면 및 EXE의 빈 대사창과 긴 대사 화면을 직접 확인함.
- 최초 구현의 검증 화면 5개를 직접 확인함. 추가 수정 뒤 전체 검사를 재실행하고 현재 데스크톱과 모바일 기웃거림 화면 4개 및 쫓아내기 화면 4개를 직접 확인함. 원본 이미지와 대사는 유지함.
- 기웃거림은 기본 이미지 전체 사용과 잘라내기 없음, 양끝 각각 1회 및 얼굴의 가장자리 위치, 반대편 표시 숨김과 동작 종료 후 완전 숨김을 대조함. 390px 모바일에서도 같은 방식을 확인함.
- 쫓아내기에서는 꺽쇠 중앙 좌표와 옴탈의 왼쪽, 숨김, 오른쪽, 숨김 및 왼쪽 순서를 대조함. 각 표시와 숨김 구간에서 40ms 간격으로 좌표를 표본 확인하여 꺽쇠 가로 50% 및 옴탈 25% 또는 75% 유지와 전환 중 중앙 이동 없음 확인함. 모바일에서도 중앙 고정과 양쪽 출현을 직접 확인함.

## 6.2 확인하지 않은 범위

- 실제 사람의 모션 입력과 게임의 성공 및 실패 분기, 정밀한 춤사위와 관절 동작 및 음향은 구현 범위에서 제외함.
- 실제 터치 기기와 다른 브라우저 및 전체 화면 전환의 실기 검증은 수행하지 않음. 사용자 시각 검토와 기획 승인 전임.
- 스토리보드를 수정하면 변환 도구와 브라우저 검증을 다시 실행해야 함. 현재 원문의 초안과 승인 미확인 상태를 변경하지 않음.
