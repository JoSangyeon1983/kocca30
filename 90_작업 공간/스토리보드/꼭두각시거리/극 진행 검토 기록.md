# 1 목적과 실행

- [극 진행 보기.html](<극 진행 보기.html>)을 브라우저에서 열고 `막 올리기`를 선택함. 별도 서버, 설치와 인터넷 연결 없이 실행함.
- 사용자 지정 스토리보드와 이미지로 극의 흐름을 보는 작업 공간 검토용 구현임. 기획서의 초안과 승인 미확인 상태는 유지함.
- HTML 옆의 CSS, JavaScript 세 파일과 `이미지` 폴더를 함께 유지함. 기존 동봉 이미지를 사용함.
- 팀원 공유용 Windows x64 단일 EXE는 [윈도우 실행 파일 배포 기록](<../../../08_산출물/덜미/꼭두각시거리/윈도우 실행 파일 배포 기록.md>)에서 별도 관리함. 사용자 지정 버전은 1.0.0이며 이 HTML 프로젝트의 패키징 출력임.

# 2 입력과 적용 범위

## 2.1 스토리보드

- 입력은 사용자가 지정한 [덜미 - 나만의 꼭두각시 스토리보드](<../덜미 - 나만의 꼭두각시 스토리보드.md>)의 `진행` 전체임. 문서에 기록된 현재 버전은 1.1.0임.
- 작업 공간 문서를 이 HTML의 직접 입력으로 사용하라는 현재 사용자 요청에 한정하여 변환함. 다른 기획서의 근거로 채택하는 작업은 수행하지 않음.
- 변환 기준 SHA-256은 `9de855fee7ebecf9f899d374aabcd0360af0e276413eba2ffe48f5e9be9ab8a7`임. 대사별 원문 행과 당시 무대 상태는 [극 진행 데이터.js](<극 진행 데이터.js>)에 보존함.
- 원문의 시작, 싸움, 재산 분배, 노잣돈과 박첨지 울음 순서를 유지함. 명시된 대사 90개와 이동 및 장면 전환 13개를 합쳐 이벤트 103개로 구성함. 이벤트 수를 원문의 단계 수로 취급하지 않음.
- 별도 소품 9개와 각 소품의 획득, 던지기, 전달하기 및 그에 따른 반응은 제외함. 재산과 노잣돈에 관한 본대사는 유지함. 제공된 무대 그림 안의 고정 장식은 그대로 표시함.

# 3 재생 방식

## 3.1 대사 표시

- 대사는 기본 38ms 간격으로 한 글자씩 추가함. 느리게 60ms, 빠르게 20ms를 선택할 수 있음. 속도는 검토용 구현에서 정한 값임.
- 한 대사의 전체 문장을 페이지로 나누지 않음. 창 높이를 넘으면 스크롤을 만들어 마지막 줄을 따라감. 다음 화자의 대사가 시작되면 창 내용을 새 대사로 바꿈.
- 위로 스크롤하여 앞부분을 읽으면 자동 따라가기를 멈춤. `이어지는 대사 보기`를 누르거나 맨 아래로 돌아오면 따라가기를 재개함.
- 타이핑 중 `모두 표시`, 대사창 클릭 또는 Space를 누르면 현재 대사만 완성함. 다음 입력에서 다음 대사로 진행함. 스크롤하는 동작은 대사 넘김과 구분함.

## 3.2 무대와 조작

- 인형 이미지를 평행 이동하고 기울여 등장, 만남, 싸움과 울음을 간략히 표현함. 관절을 분리하거나 다른 자세를 생성하지 않음.
- 등장과 퇴장 같은 이동 이벤트는 약 1초 후 다음 이벤트로 이어짐. 대사는 기본 수동 진행이며 `자동 진행` 선택 시 타이핑 완료 1.4초 후 다음으로 진행함. 원문에 없는 시간은 이 검토본의 재생값임.
- `이전`, `장면`, `처음부터`, `전체 화면` 제공함. 이전 대사나 장면으로 이동하면 해당 시점의 인물 배치를 복원함.

# 4 숫자 5와 7 확인

| 숫자 | 요청 당시 스토리보드 위치 | 판단 |
|---|---|---|
| 5 | `꼭두각시 등장`의 박첨지 대사 중 `율묵이가 이마라도 때렸나? 5 울퉁불퉁하고` | 독립 숫자가 문장 사이에 끼어 있음 |
| 7 | `덜머리집 등장`의 산받이 대사 중 `짚으로 7 만든 조상의 위패` | 독립 숫자가 수식어와 동사 사이에 끼어 있음 |

- 숫자의 용도 보고를 위해 [남사당놀이 - 덜미: 셋째. 꼭두각시 거리](<../../../05_참고 자료/기술 자료/남사당놀이/남사당놀이 - 덜미.md#413-셋째-꼭두각시-거리>)의 대응 문장만 대조함. `율묵이가 마빡을 때렸나, 우툴두툴하고`와 `짚으로 만들어도 신주는 신주법대로`에는 두 숫자가 없음. 해당 연희본의 다른 대사를 HTML로 가져오지 않음.
- 주석 번호의 잔재로 추정되지만 대응 주석과 최초 유입 경로는 미확인임. 두 숫자가 뜻하는 주석 내용을 확정하지 않음.
- 제작 중 입력 원문에서 두 숫자와 `꼭두가시` 표기가 이미 정리된 것을 재확인함. Codex가 스토리보드를 수정하지 않았으며 HTML은 그 현재 수정본으로 생성함. 이번 변환의 추가 교정 목록은 비어 있음.

# 5 검증과 한계

## 5.1 실행 결과

- Windows의 Edge `155.0.4283.62`를 임시 프로필의 헤드리스 모드로 실행함. 실제 로컬 `file` URL로 HTML을 열어 검증함.
- 최초 검증일은 2026-10-21이며 2026-10-22 중단 복구 후 재검증함. 현재 원문의 SHA-256과 변환 데이터 및 대사 90개의 화자, 전체 문장과 원문 행 번호 일치를 별도 확인함. 최신 실행 시각은 검증 JSON의 `verifiedAt`에 UTC로 기록함.
- 대사 90개의 순서, 화자와 전체 문자열을 입력 데이터와 대조함. 장면 이동과 처음부터, 이전 대사, 자동 진행, 싸움 상태, 마지막 페이드와 종료까지 검사함. JavaScript 실행 예외 없음.
- 시간 경과에 따라 글자가 증가하고, 타이핑 완료 전에도 긴 대사가 창 높이를 넘으면 자동 스크롤되는 것을 확인함. 위로 읽기와 마지막 줄로 복귀하는 조작도 확인함.
- 1280×960 데스크톱과 390×844 모바일 배치를 검사함. 모바일에서는 무대 아래에 대사창을 배치하며 가로 넘침 없음. 이동 이벤트 중에도 재생 조작의 위치가 유지되도록 대사창 공간을 확보함.
- 재검증의 긴 대사 캡처에서 화면 조각이 반복되는 현상을 발견함. 검증용 브라우저에 `--disable-gpu`를 적용하고 캡처 전 프레임과 300ms 대기를 추가한 뒤 전체 검사를 재실행함. 갱신한 데스크톱, 긴 대사와 모바일 화면을 직접 확인함.

## 5.2 확인하지 않은 범위

- 실제 터치 기기, Safari와 Firefox 및 브라우저별 전체 화면 전환은 미검증임.
- 동작과 표정은 원문 연기를 재현한 것이 아닌 이동과 기울임의 간략 표현임. 소품 상호작용, 음향과 정확한 동작 검증 대상 아님.
- 사용자 시각 검토와 기획 승인 전임. 원문 수정 후에는 재변환과 재검증이 필요함.
