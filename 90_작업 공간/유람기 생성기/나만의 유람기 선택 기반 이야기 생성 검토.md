# 1 검토 결론과 문서 상태

- **권고안: 선택 결과가 누적되는 이야기 구조에 다음 장면의 사전 준비와 지연 시 대체 진행을 결합하는 방식임.**
- 사용자가 화자를 설정한 뒤 극을 시작하고, 제시된 선택지를 선택하면서 이야기를 진행하는 요구사항을 본 문서에 반영함.
- 구체적인 생성 구조와 시간값은 Codex의 검토 제안임. 사용자 요구사항의 기록과 구현안의 채택을 구분하며, 기존 기획서 원본은 수정하지 않음.

## 2.2 사용자 요구사항

근거: 2026-11-10 현재 사용자 지시. 아래 항목은 해당 지시의 의미 단위별 요약임.

| 식별자 | 사용자 지정 내용 | 적용 범위 |
|---|---|---|
| R1 | 화자의 이름, 연령대, 성별 설정 | 극 시작 전 설정 |
| R2 | 화자 설정 완료 후 극 시작 | 설정에서 플레이로의 연결 |
| R3 | 극에서 제시된 선택지를 유저가 선택 | 이야기 진행 입력을 자유 서술 문답에서 선택으로 변경 |
| R4 | 선택에 따라 이야기의 창발적 진행 | 선택이 이후 사건에 영향을 주는 생성 구조 |
| R5 | 키오스크에서 AI 답변을 무작정 기다릴 수 없음 | 생성 지연의 상한과 대체 진행 필요 |

- 이름을 설정하는 구체적인 입력 수단은 미정임. 이야기의 선택 입력으로 변경했다는 이유로 이름 입력에서도 키보드와 음성이 모두 삭제된 것으로 간주하지 않음.
- 사용자 표현에 따라 설정 대상을 ‘화자’로 표기함. 기존 문서의 ‘주인공’ 및 진행을 맡는 박첨지와 화자의 관계는 별도 정리 필요함.

# 3 창발성과 응답 속도의 중간안

## 3.1 방식 비교

아래 비교와 권고는 설계 검토 제안이며, 실제 속도와 품질을 측정한 결과가 아님.

| 방식 | 이야기 변화 | 대기 처리 | 판단 |
|---|---|---|---|
| 완성된 모든 분기를 사전 제작 | 제작한 경로 안에서 변화 | 준비된 콘텐츠로 즉시 진행 가능 | 선택형 콘텐츠에는 적합하나 새 사건의 창발 범위가 제한됨 |
| 선택할 때마다 전체 다음 내용을 실시간 생성 | 선택과 이전 사건을 반영한 새 전개 가능 | 매번 외부 생성 완료에 의존 | 키오스크의 일정한 진행 속도를 확보하기 어려움 |
| 현재 상태로 다음 장면을 미리 생성하고, 늦으면 준비된 장면으로 연결 | 이전 선택의 누적 결과로 사건과 선택지 변화 | 생성 대기 상한을 두고 계속 진행 | 우선 검토할 중간안 |

## 3.2 권고안의 기본 구조

- 사전 준비 대상: 도입 장면, 인물의 목표, 사건 재료, 사용 가능한 배경과 연출, 지연 시 사용할 연결 장면임. 완성된 이야기의 모든 분기를 미리 만드는 방식은 아님.
- 실시간 생성 대상: 지금까지의 사건과 선택을 바탕으로 한 다음 사건, 인물의 반응, 대사와 다음 선택지임. 누적된 상태에 따라 사건의 내용 자체가 달라지도록 함.
- 진행 시스템의 역할: 선택 결과 저장, 이미 일어난 사실 유지, 준비된 생성 결과의 적용 여부 판단 및 대기 상한 관리임.
- 최종 유람기의 역할: 실제 플레이에서 확정된 사건을 읽기 좋은 이야기로 정리함. 최종 생성 과정에서 선택과 사건의 결과를 다시 결정하지 않음.

## 3.3 제안 진행 흐름

| 순서 | 유저에게 보이는 진행 | 뒤에서 준비할 내용 |
|---|---|---|
| 1 | 이름, 연령대, 성별로 화자 설정 | 설정과 초기 이야기 상태 저장 |
| 2 | 준비된 도입 장면과 첫 선택지 표시 | 현재 선택지별 다음 장면 후보 생성 시작 |
| 3 | 장면을 보고 선택지를 선택 | 선택 대기 중 다음 장면 후보 준비 지속 |
| 4 | 선택에 맞는 짧은 반응을 즉시 표시 | 선택 결과 확정, 해당 후보의 준비 상태 확인 |
| 5 | 준비된 다음 장면 또는 대체 장면으로 진행 | 갱신된 상태를 바탕으로 다음 선택의 후보 준비 |
| 6 | 이야기 마무리 후 유람기 감상 | 확정 사건을 바탕으로 본문 정리와 결과물 제작 |

- 순서는 본 검토안의 설계 추가임. 기존 기획서의 단계 수와 선택 횟수를 그대로 확정한 것이 아님.
- 도입과 첫 선택지는 화자 설정값을 적용해 바로 표시할 수 있는 형태로 준비하는 안임.
- 다음 후보의 사전 생성 범위는 현재 선택지의 바로 다음 장면까지로 제한함. 이후 모든 갈래를 재귀적으로 생성하지 않으며, 선택되지 않은 후보는 이후 진행에 적용하지 않음.
- 유저가 일찍 선택하거나 생성이 느리면 후보 준비가 완료되지 않을 수 있음. 사전 생성만으로 지연이 없어지는 것으로 간주하지 않음.

# 4 선택이 이야기의 원인이 되게 하는 조건

## 4.1 상태와 사건의 누적

- 화자 설정 외에, 실제 발생한 사건과 선택, 인물 관계, 보유 물건, 해결되지 않은 문제를 이야기 상태로 유지하는 안임.
- 다음 장면 생성 시 현재 상태를 전달하고, 앞선 선택 때문에 달라진 상황을 다음 사건이나 선택지에 드러내도록 함.
- 인물의 목표와 상황이 맞물리며 새 사건이 생기도록 함. 같은 사건의 표현만 달라지는 결과는 창발적 전개의 달성으로 보지 않음.

## 4.2 선택 결과의 확정

- 선택지를 표시할 때 각 선택의 즉시 결과와 그에 맞는 짧은 반응을 함께 준비하는 안임. 유저가 선택하면 해당 결과만 확정하고 표시함.
- 아직 생성되지 않은 구체적인 성공 여부나 후속 사건을 즉시 반응에서 먼저 단정하지 않음. 선택한 행동의 실행과 확정된 변화까지만 안내함.
- 선택 이후 생성할 사건은 확정된 결과를 이어받음. 예를 들어 물건을 건넸다면 다음 장면에서 해당 물건을 계속 소지한 상태로 되돌리지 않음.
- 이전 상태를 기준으로 늦게 도착한 생성 결과는 현재 이야기와 대조한 뒤 사용함. 대체 장면으로 이미 진행했다면 이전 결과로 화면과 사건을 되돌리지 않음.

## 4.3 인과관계 예시

아래 내용은 구조 설명용 가상 예시이며, 덜미의 실제 극 내용으로 채택한 사건이 아님.

| 선택과 이전 상황 | 누적 결과 | 이후 전개에 드러날 차이 |
|---|---|---|
| 길에서 만난 인물에게 가진 물건을 건넴 | 물건 소유 해제, 도움을 준 관계 기록 | 그 인물이 이후 정보를 알려 주거나 도움을 돌려줄 여지 발생 |
| 물건을 간직하고 다른 방법을 제안함 | 물건 유지, 제안한 방법 기록 | 물건을 다른 문제에 쓰거나 제안의 결과를 마주할 여지 발생 |

- 두 선택이 당장 같은 장소로 이어져도 관계와 물건의 차이가 이후 사건에 남아야 함. 장면의 이동 경로만으로 선택의 의미를 판단하지 않음.

# 5 키오스크의 대기 처리 제안

## 5.1 생성 준비 상태에 따른 진행

| 상태 | 화면 진행 | 이야기 처리 |
|---|---|---|
| 선택한 다음 장면의 생성과 검토 완료 | 짧은 선택 반응 후 해당 장면 표시 | 선택 결과를 이어받은 생성 내용 적용 |
| 아직 준비 중이나 대기 상한 이내 | 준비된 선택 반응 표시 중 다음 장면 확인 | 현재 선택에 해당하는 후보만 대기 |
| 상한 초과 또는 생성 실패 | 상태에 맞는 준비된 연결 장면과 다음 선택지 표시 | 선택 결과를 유지한 채 계속 진행 |

- 지연 시 연결 장면은 새 AI 호출 없이 구성할 수 있도록 사건 재료와 조건을 사전 준비하는 안임. 준비되지 않은 다른 분기의 결과를 대신 보여주지 않음.
- 대기 상한이 지나면 다음 선택까지 진행 가능한 장면으로 전환함. 짧은 문장만 보여준 채 같은 생성 응답을 계속 기다리는 구조는 피함.
- 연출 길이를 늘리거나 선택 버튼을 늦게 활성화하여 생성 시간을 무제한 확보하는 방식은 사용하지 않는 안임.

## 5.2 시간값과 생성 범위

- 시험용 제안값: 선택 후 짧은 반응은 즉시 표시하고, 그 반응이 끝난 뒤 다음 장면을 기다리는 추가 시간은 최대 2초로 설정해 검증함. 확정 운영값이 아니며, 선택부터 다음 조작 가능 시점까지의 전체 시간도 함께 측정함.
- 플레이 중에는 다음 사건과 선택지에 필요한 짧은 텍스트를 우선 생성하는 안임. 배경과 인물 연출은 준비된 자산을 사용하고, 실시간 이미지 및 음성 생성 완료를 다음 선택의 필수 조건으로 두지 않음.
- 고품질 삽화, 전체 낭독과 전자책 조립은 결과물 제작 단계에서 처리하는 안임. 이 단계도 별도 대기 상한과 실패 시 제공 범위가 필요하며, 플레이 중 대기를 마지막 화면으로 무제한 넘기지 않음.
- 선택지별 사전 생성은 호출량과 비용을 늘릴 수 있음. 선택지 수, 동시 생성 수와 결과 길이는 실제 기기의 지연 및 운영 비용을 함께 측정한 뒤 결정함.

## 6.2 먼저 검증할 범위

- 텍스트와 선택 버튼으로 짧은 극 한 편을 진행하는 검증안임. 생성 모델과 동시 호출 방식의 선정은 미정임.
- 같은 시작 조건에서 서로 다른 선택을 했을 때 후속 사건과 관계가 달라지는지 확인함. 이름과 문장 표현만 바뀌는 결과와 구분함.
- 빠른 선택, 느린 생성과 생성 실패 조건에서 반응 시간 및 다음 조작까지 걸린 시간, 준비된 장면 사용 비율과 호출 비용을 측정함.
- 대체 장면을 사용한 경우에도 선택 결과와 앞선 사실이 유지되는지 확인함. 최종 유람기의 사건 일치 여부도 함께 확인함.
