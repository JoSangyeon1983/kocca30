# 1 목적과 문서 상태

- 사용자에게 설명한 최신 이야기 진행 데이터 스키마를 다음 작업의 검토 출발점으로 보존함.
- 사용자 요구사항과 Codex의 구현 제안을 구분함. 문서화 요청을 스키마의 최종 승인이나 정식 기획 반영으로 취급하지 않음.
- 이전에 제시했다가 철회한 다수의 설정 테이블, 사전 주인공 목표와 단계별 고정 줄거리를 현재 스키마에 포함하지 않음.
- 기존 AvatarType, ContentPolicy는 사용자가 구성했다고 설명한 상태임. 실제 구글 스프레드시트와 JSON 파일은 열람하지 않았으며 실제 칼럼과 값의 일치는 미확인임.

# 2 사용자 요구사항

## 2.1 인물과 선택 설정

- 주인공은 사용자 아바타이며, 입력은 이름, 성별과 연령대임. 별도 나이 입력 없음.
- 아바타 유형은 남자 아이, 여자 아이, 남자 청소년, 여자 청소년, 남자 어른, 여자 어른의 6개임.
- 박첨지는 화자와 진행자를 맡음. 아바타 대사의 SpeechInstruction과 박첨지의 해설 지침은 구분함.
- 사용자가 선택하는 이야기 유형은 위협-구원형, 권력 풍자형, 위선 폭로형, 욕심과 다툼형의 4개임.

## 2.2 진행과 창발성

| 단계 | 선택지 수 | 사용자 선택 횟수 |
|---|---:|---:|
| 발단 | 3 | 1 |
| 전개 | 3 | 1 |
| 절정 | 3 | 1 |
| 위기 | 3 | 1 |
| 결말 | 0 | 0 |

- 단계 순서는 발단, 전개, 절정, 위기, 결말임. 일반적인 다른 서사 순서로 바꾸지 않음.
- AI가 TRPG의 GM처럼 상황과 선택지를 생성하고, 선택한 행동과 이전 사건에서 결과 및 다음 상황을 생성하는 구성임.
- 시작 전에 주인공의 목표와 결말을 고정하지 않음. 선택지는 동일한 목표의 해결 방법만이 아니라 관여 대상이나 방향이 다른 행동도 제시할 수 있음.
- 인물의 관계, 의도, 등장 계기와 행동 범위를 이야기마다 작성자에게 모두 지정하도록 요구하지 않음.
- 해결 여부를 포함한 최종 상황이 선택으로 달라져야 함. 미리 정한 목표의 성공 점수만으로 결말을 판단하는 구성으로 제한하지 않음.

## 2.3 데이터 관리

- 설정 데이터는 구글 스프레드시트에서 관리하고 JSON으로 변환함.
- 주석 처리한 열과 행을 JSON에서 제외할 수 있는 기존 기능을 활용함.
- 작성자는 주석 칼럼에서 Enum 문자열을 관리하고, 출력 ID 칼럼은 VLOOKUP으로 대응하는 숫자를 반환하는 방식임.
- 칼럼명은 기존 논의의 PascalCase 표기를 사용함. Enum의 실제 숫자 배정과 변환기의 제외 표기는 본 문서에서 새로 확정하지 않음.
- 콘텐츠의 공통 허용 범위와 연령별 차등 정책은 구분하며 성인용 내용은 제외함.

# 3 설정 데이터의 구성

## 3.1 관리 단위

| 구분 | 관리 대상 | 작성 단위 |
|---|---|---|
| 구성 완료로 전달받은 테이블 | AvatarType | 아바타 유형 하나 |
| 구성 완료로 전달받은 테이블 | ContentPolicy | 연령별 정책 하나 |
| 추가 제안 테이블 | StoryType | 이야기 유형 하나 |
| 추가 제안 테이블 | StoryMaterial | 소재 얼개 하나 |
| 공용 생성 설정 | 공통 GM 지침과 콘텐츠 공통 제한 | 모든 이야기에 재사용하는 지침 |

- 추가 설정 테이블은 2개임. 이야기 한 편마다 테이블을 새로 만드는 구성이 아님.
- 아래의 PlaySession, 장면과 선택지는 자동 생성되는 실행 데이터 구조이며 스프레드시트 작성용 테이블 목록이 아님.
- 공통 GM 지침은 공용 프롬프트 또는 설정으로 관리하는 제안임. 구체적인 파일 형식과 저장 위치는 미정임.

## 3.2 StoryType

- 한 행은 이야기 유형 하나이며 총 4행임.
- 유형별 GenerationInstruction은 한 번 작성하여 여러 소재에 재사용함.

| 칼럼 | 자료형 | 내용 |
|---|---|---|
| StoryTypeId | 정수, Enum | 이야기 유형 식별값 |
| 주석 StoryType | 문자열 | Enum 이름 조회용. JSON 제외 |
| DisplayName | 문자열 | 유형 표시명 |
| GenerationInstruction | 문자열 | 유형의 성격을 사건과 선택지에 반영하는 생성 지침 |

- 표시명은 위협-구원형, 권력 풍자형, 위선 폭로형, 욕심과 다툼형임.
- 지침은 해당 유형의 특징을 드러내는 방식이며 특정 사건, 주인공 목표나 해결 방법을 강제하지 않음.
- 예시: 권력 풍자형에서는 권력자의 명분과 행동의 모순을 드러내되, 사용자가 반드시 저항하거나 권력자를 몰아내도록 지정하지 않는 방향임.
- 유형별 지침의 실제 값은 후속 작업에서 작성할 사항임.

## 3.3 StoryMaterial

- 한 행은 소재의 얼개 하나임. 단계별 줄거리와 선택별 분기를 작성하지 않음.

| 칼럼 | 자료형 | 내용 |
|---|---|---|
| StoryMaterialId | 정수 | 소재 식별값 |
| DisplayName | 문자열 | 관리용 소재명 |
| Premise | 문자열 | AI가 이야기를 시작하고 확장할 소재의 얼개 |

| StoryMaterialId | DisplayName | Premise |
|---:|---|---|
| 1 | 평안감사의 사냥 | 평안감사가 사냥을 핑계로 백성들을 괴롭히는 이야기. |

- 위 행의 ID는 구조 설명용 예시이며 실제 번호 배정이 아님. 얼개는 사용자가 제시한 소재 설명이며 원전 대조 결과를 뜻하지 않음.
- 아바타의 등장 계기, 인물의 구체적인 의도와 관계, 첫 장면은 얼개와 선택한 유형을 바탕으로 AI가 생성함.
- StoryMaterial에 StoryTypeId를 고정하는 구성은 두지 않음. 세션에서 유형과 소재를 함께 참조하는 제안임.
- 소재 선정 방식과 유형별 조합 적합성은 미정임. 독립 참조가 모든 소재와 유형 조합의 적합성을 보장하는 것은 아님.

# 4 공통 GM 지침의 역할

## 4.1 이야기 운영

- 박첨지는 화자와 진행자이며 사용자 아바타가 행동함.
- 앞의 네 단계마다 3지선다 선택을 한 번 받고 결말에서는 선택을 받지 않음.
- 아바타의 목표와 최종 결말을 시작 전에 확정하지 않음.
- 선택한 행동과 확정된 사건에서 결과를 도출하고 인물의 대응으로 다음 상황을 만듦.
- 인물의 의도와 관계는 발생한 사건에 따라 달라질 수 있으며, 사전 행동 목록으로 고정하지 않음.

## 4.2 단계와 결말

- 단계는 체험의 진행 길이를 관리하는 틀이며 고정 사건으로 합류시키는 장치가 아님.
- 위기 단계가 남았다는 이유로 이미 해결한 일을 취소하거나 선택의 성과를 지우지 않음.
- 네 번째 선택 결과까지 반영해 실제로 달라진 상황을 결말로 마무리함.
- 공통 콘텐츠 제한은 공용 설정으로 관리하고 ContentPolicy는 그 범위 안에서 연령별 차이를 적용함.
- 지침의 최종 문안과 실제 생성 준수 여부는 추가 검증 대상임.

# 5 실행 중 자동 저장할 데이터

## 5.1 PlaySession

- 한 번의 플레이를 저장하는 구조임. 구글 시트에서 작성자가 입력할 설정 데이터가 아님.

| 필드 | 자료형 | 내용 |
|---|---|---|
| SessionId | 문자열 | 플레이 식별값 |
| AvatarName | 문자열 | 사용자가 입력한 이름 |
| AvatarTypeId | 정수 | 성별, 연령대, 어투와 콘텐츠 정책 참조 |
| StoryTypeId | 정수 | 선택한 이야기 유형 |
| StoryMaterialId | 정수 | 적용한 소재 |
| Status | Enum | 생성 중, 선택 대기, 완료, 오류 |
| Scenes | 장면 배열 | 실제 생성한 장면과 선택 기록 |

- 성별과 연령대 등은 AvatarType에서 복원할 수 있다는 전제임. 실제 시트 구조와 연결을 후속 확인함.
- Status의 Enum 이름과 숫자값은 아직 정하지 않음.
- Scenes는 세션에 속한 장면 목록임. 이를 별도 DB 테이블로 나눌지는 구현 단계의 저장 방식 문제이며 현재 확정하지 않음.

## 5.2 장면

| 필드 | 자료형 | 내용 |
|---|---|---|
| Stage | Enum | 발단, 전개, 절정, 위기, 결말 |
| Narration | 문자열 | 박첨지 해설과 인물 대사를 포함한 실제 이야기 |
| Choices | 선택지 배열 | 앞의 네 단계는 3개, 결말은 빈 배열 |
| SelectedChoiceId | 정수 또는 null | 사용자가 선택한 항목 |
| Events | 문자열 배열 | 해당 장면에서 실제로 확정된 사건 |

- Stage의 Enum 이름과 숫자값은 미정임.
- SelectedChoiceId는 선택 전과 결말에서 null임. 장면 단계와 선택지 배열을 함께 보아 구분함.
- 직전 선택의 결과는 다음 장면의 Events에 기록함. 위기의 마지막 선택 결과는 결말 장면에 기록함.
- 발단의 Events에는 첫 장면에서 확정한 사건을 기록할 수 있음. 아직 선택하지 않은 행동의 결과를 확정하지 않음.
- Events는 실행 중 사실 기록임. 인물의 주장, 의도와 추측을 사실로 바꾸어 기록하지 않음.

## 5.3 선택지

| 필드 | 자료형 | 내용 |
|---|---|---|
| ChoiceId | 정수 | 해당 장면 안에서 1, 2, 3 |
| Text | 문자열 | 사용자가 선택할 행동 |

- ChoiceId는 장면 안에서만 식별함. 다른 장면에서도 같은 숫자를 사용할 수 있음.
- 선택지에 후속 줄거리와 성공 결과를 미리 저장하지 않는 제안임.
- 선택 후 AI가 누적 상황을 근거로 결과와 다음 장면을 생성함. 판정의 구체적인 방법과 일관성 검사는 미정임.

# 6 생성 입력과 기록 처리

## 6.1 첫 생성과 후속 생성

| 시점 | 전달할 내용 |
|---|---|
| 첫 생성 | 아바타 설정, 콘텐츠 정책, 이야기 유형 지침, 소재 얼개, 공통 GM 지침 |
| 후속 생성 | 첫 생성의 설정과 지침, 이미 생성한 장면과 실제 선택 기록 |

- 네 번의 선택으로 제한된 초기 구현에서는 전체 진행 기록을 유지해 검증하는 제안임.
- 초기부터 별도 요약 호출과 복잡한 기억 테이블을 도입하지 않음. 실제 출력 길이, 지연과 토큰 비용을 측정한 뒤 입력 축소 필요성을 판단함.
- 현재 구조만으로 지연이나 비용 절감이 검증된 것은 아님.

## 6.2 선택 확정과 생성 대기

1. 사용자가 선택하면 해당 장면의 SelectedChoiceId를 저장함.
2. 세션 Status를 생성 중으로 변경함.
3. 누적 기록으로 다음 장면 생성을 요청함.
4. 다음 장면의 Narration과 Events 및 Choices를 함께 반영함.
5. 다음 장면이 결말이면 완료, 아니면 선택 대기로 변경함.

- 선택 저장은 행동 선택의 확정이며 행동의 성공 확정이 아님.
- 선택 직후 생성이 중단되면 결과가 없는 생성 대기 상태와 결과가 반영된 상태를 구분해야 함.
- 중복 요청 방지, 재시도, 대체 장면과 늦은 응답의 적용 방지는 별도 구현 검토 대상으로 남김.

# 7 검토 범위와 후속 작업

## 7.1 수행한 검토

- 대화의 요구사항과 최신 제안 구조를 대조함. 사용자 작성 설정과 자동 실행 기록을 구분함.
- 별도 AI 검토자에게 스키마 후보와 요구사항을 제공하여 반례 검토를 수행함.
- 방향이 달라지는 선택에서 유형 지침이 고정 줄거리로 작동하지 않아야 함을 확인함.
- 선택 직후 중단과 재개에서 행동 선택과 결과 확정의 구분이 필요함을 확인함.
- 위 검토는 설계 수준의 사고 실험임. 실제 프로그램 실행, 구글 시트 변환과 모델 API 연동 검증을 뜻하지 않음.

## 7.2 다음 작업에서 이어갈 내용

- StoryType.GenerationInstruction의 4개 유형별 실제 문안 작성 및 선택 경로 대입 검토함.
- StoryMaterial.Premise의 작성 예시와 소재 선정 방식, 유형과 소재 조합 처리 방식을 검토함.
- 공통 GM 지침의 실제 문안과 다음 장면 생성 요청 및 응답 형식을 구체화함.
- 실제 AvatarType, ContentPolicy 시트와 참조 ID 및 Enum 숫자값을 대조함.
- 재시도와 중복 생성 방지, 지연 시 진행, 전체 경로의 인과관계와 토큰 및 시간 비용을 검증함.

## 7.3 기존 검토안과의 관계

- [나만의 유람기 선택 기반 이야기 생성 검토](<나만의 유람기 선택 기반 이야기 생성 검토.md>)는 이전 요구사항과 사전 생성 검토의 기록임.
- 화자와 아바타의 구분, 5개 단계와 4회 선택, 사전 주인공 목표를 요구하지 않는 방향은 현재 사용자 지시를 본 문서에 기록함.
- 이전 문서의 후보 사전 생성, 즉시 결과 준비와 시간값은 미채택 제안임. 본 문서의 최소 스키마와 자동으로 결합하거나 승인된 기준으로 취급하지 않음.
- 내일 후속 작업을 이어가기로 한 사용자 요청에 따라 현재 문서화 범위에서 작업을 마침.
