# 1 목적과 현재 구성

- [index.html](<../옴탈 채검하기 시간 테스트/index.html>)을 직접 열어 대기, 암기와 입력을 시험하는 서버 없는 HTML임. 별도 Python 실행과 상주 프로세스를 사용하지 않음.
- 공유 폴더에는 HTML과 [설정.json](<../옴탈 채검하기 시간 테스트/설정.json>) 및 [resources](<../옴탈 채검하기 시간 테스트/resources/>)만 남김. 이 제작 폴더의 원본 코드와 검증 자료 및 본 기록은 공유하지 않아도 됨.
- 공통 노트 유지 시간과 노트 사이 간격을 바꾸고 같은 순서로 재시험할 수 있음. 기획서의 시간값을 확정하거나 원본 PNG를 수정한 작업은 아님.
- 기존 서버는 종료함. 서버 코드와 이전 서버용 검증 및 실행 보조는 종료 작업으로 보관함. 중복 실행.cmd와 Python 캐시는 공유 폴더에서 제거함.

# 2 입력과 진행 기준

## 2.1 기획서와 사용자 지시

- 입력 문서는 [덧뵈기 - 탈놀음 한바탕 기획서: 옴탈 채검하기](<../../04_상세 기획/덧뵈기 - 탈놀음 한바탕/덧뵈기 - 탈놀음 한바탕 기획서.md#3-옴탈-채검하기>)임. 확인한 문서 정보의 마지막 버전은 4.2.0, 해당 날짜는 2026-11-02임.
- 대기 시 정면 옴탈과 빈 노트 네 개를 표시함. 암기에서는 연속 중복을 제외한 무작위 방향 네 개를 좌상, 우상, 좌하, 우하 노트에 순서대로 표시함. 지나간 화살표는 기본 상태로 남김.
- 입력 시 화살표를 초기화하고 현재 노트에 물음표와 잔여 시간을 표시함. 사용자 수정 지시에 따라 첫 입력에 즉시 성공 또는 실패를 표시하고 추가 입력은 받지 않음.
- 유지 시간은 입력 시점과 관계없이 끝까지 진행함. 유지 종료부터 간격을 세고 간격 종료에 다음 노트를 시작함. 입력이 없으면 유지 종료에 시간 초과로 판정함. 마지막 노트도 전체 주기를 마친 뒤 완료함.
- 실패와 시간 초과 노트에는 정답 방향을 표시함. 실제 입력과 응답 시간은 결과 표에 따로 표시함. 실제 카메라 입력은 키패드로 대체한 시험 구현임.

## 2.2 시간 설정

| JSON 항목 | 화면 항목 | 의미 |
|---|---|---|
| `noteHoldSeconds` | 공통 노트 유지 시간 | 암기에서는 방향 표시, 입력에서는 응답을 받는 시간임. 입력 직후 판정을 표시해도 유지 시간 타이머는 노트 시작 기준으로 계속 진행함. |
| `noteGapSeconds` | 노트 사이 간격 | 유지 시간 종료 후부터 세는 시간임. 종료 시 다음 노트를 시작하며 입력 결과는 이 구간에도 남음. |

- 한 노트의 전체 주기는 `유지 시간 + 간격`임. 첫 입력 시점은 판정 표시의 시작 시각에만 영향을 주며 다음 노트 시점을 변경하지 않음.
- 유지 시간은 0.05~60초, 간격은 0~60초의 유한한 숫자만 허용함. 진행 중에는 설정 편집을 잠금. 간격 0초는 유지 종료에 바로 다음 노트를 시작하는 조건임.
- 제작 시점의 기존 [설정.json](<../옴탈 채검하기 시간 테스트/설정.json>) 값은 유지 1초와 간격 1.2초이며 HTML에 시작값으로 내장함. 실제 실행에서는 브라우저의 마지막 저장값 또는 연결한 JSON을 우선 사용함.
- 이전 네 항목 형식의 원본은 [설정 통합 전.json](<설정 통합 전.json>)으로 남김. 현재 화면은 두 항목 JSON을 사용함.

# 3 실행과 파일 저장

## 3.1 시작과 종료

1. 공유 폴더 전체를 전달하고 [index.html](<../옴탈 채검하기 시간 테스트/index.html>)을 더블클릭함. Node와 Python 설치 없이 브라우저에서 실행함.
2. 왼쪽 두 값을 입력하고 `새 순서 시작`을 누름. `같은 순서로 재시험`은 직전 방향 순서를 유지하며 변경한 시간값을 적용함.
3. 숫자 키패드와 일반 숫자열의 `1=상`, `2=하`, `3=좌`, `4=우`로 입력함. 누른 키의 자동 반복은 다음 노트에 사용하지 않음.
4. `대기로 초기화`는 진행 중인 시험을 중단하고 빈 노트와 정면 옴탈로 복귀함. 시간 설정과 직전 순서는 유지함.
5. 사용 후 브라우저 탭을 닫음. 이 테스트를 위한 별도 서버 종료 작업은 없음. 다른 탭으로 이동해 화면이 숨겨지면 진행 중인 시험은 중단함.

## 3.2 설정의 보관과 JSON 연결

- 값 변경 후 약 0.45초가 지나면 브라우저 저장소에 자동 보관하고 다시 열 때 복원함. 탭을 닫을 때도 유효한 현재 값을 보관함. 브라우저 데이터 삭제나 HTML 경로 변경 시에는 JSON을 다시 읽어야 할 수 있음.
- `JSON 연결`에서 기존 [설정.json](<../옴탈 채검하기 시간 테스트/설정.json>)을 선택하면 해당 파일을 읽음. 브라우저의 쓰기 권한을 허용한 경우 이후 변경값을 연결 파일에도 자동 저장함. 파일 핸들은 브라우저에 기억하고 재실행 시 읽기 권한이 유지돼 있으면 다시 읽음.
- `JSON 저장`은 연결 파일에 저장함. 연결 파일이 없으면 저장할 JSON 파일과 위치를 선택함. 브라우저가 권한 재확인을 요구하면 이 버튼에서 확인함.
- 직접 파일 연결을 지원하지 않는 환경에서는 일반 파일 선택으로 JSON을 불러오고 JSON 저장은 다운로드로 처리함. 연결하지 않아도 브라우저 저장값으로 게임 시험을 시작할 수 있음.
- 파일 접근은 선택한 파일에 대해 사용자 권한을 받는 브라우저 API로 처리함. 파일 핸들 보관과 권한 재확인은 [Chrome 공식 문서: File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)의 방법을 따름. `file:` 문맥의 보안 컨텍스트 분류는 [MDN Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)를 확인함.

## 3.3 결과 기록

- 시험 완료 후 성공 개수와 정답, 실제 입력, 실패 이유 및 응답 시간을 표시함.
- `시험 기록 저장`은 현재 설정과 방향 순서, 판정 및 시간 이벤트를 JSON으로 다운로드함. 브라우저의 다운로드 위치와 저장 대화상자 설정을 따름.
- 시간 이벤트의 `plannedMs`와 `observedMs`는 시작 기준 밀리초임. `input_received`와 `judgment`는 입력 시각, `gap_start`는 고정된 유지 종료, `input_open`은 고정된 다음 노트 시작을 대조할 수 있음.

# 4 파일 구성과 수정 방법

| 파일 | 역할 |
|---|---|
| [index.html](<../옴탈 채검하기 시간 테스트/index.html>) | 직접 열어 쓰는 실행용 HTML임. 스타일과 실행 코드 및 제작 시점 시작값을 내장함. |
| [설정.json](<../옴탈 채검하기 시간 테스트/설정.json>), [resources](<../옴탈 채검하기 시간 테스트/resources/>) | 팀원에게 함께 전달할 현재 설정과 PNG 14개임. |
| [화면 템플릿.html](<화면 템플릿.html>), [style.css](<style.css>) | 화면을 수정하는 원본임. |
| [app.mjs](<app.mjs>), [engine.mjs](<engine.mjs>), [storage.mjs](<storage.mjs>) | 화면, 시간과 판정 및 브라우저 설정 저장 원본임. |
| [빌드.mjs](<빌드.mjs>) | 원본과 공유 폴더의 설정 JSON을 실행 HTML로 묶는 제작용 도구임. 수정 후 위키 루트에서 `node "90_작업 공간/옴탈 채검하기 제작/빌드.mjs"`를 실행함. 공유 폴더 이름을 바꾼 경우 새 공유 폴더 경로를 마지막 인수로 전달함. |

- 이미지는 [resources](<../옴탈 채검하기 시간 테스트/resources/>)의 사용자 제공 PNG 14개를 그대로 사용함. HTML과 설정 JSON 및 resources를 같은 위치 관계로 함께 이동하면 됨.
- 설정값 변경은 화면에서 수행함. JSON이나 소스 코드를 수정해 제작용 시작값을 다시 내장하려면 빌드를 실행함. 연결한 JSON은 화면 재실행에서 읽으므로 값 변경 때마다 빌드할 필요는 없음.

# 5 검증 결과와 한계

## 5.1 이번에 확인한 범위

- 공유 폴더에는 `index.html`, `설정.json`과 `resources` 세 항목만 존재함. 제작 코드와 검증 기록을 분리한 뒤 이 구성만으로 아래 브라우저 검증을 재실행함. HTML과 설정 JSON 및 PNG 14개의 SHA-256이 정리 전후 동일함. 검증 출력은 본 제작 폴더에만 저장함.
- [시간 동작 검증.mjs](<시간 동작 검증.mjs>)의 11개 검사 통과함. 즉시 판정, 입력 시점과 독립적인 유지 종료와 간격 및 마지막 주기를 확인함.
- [브라우저 검증.mjs](<브라우저 검증.mjs>)는 Python이나 HTTP 서버를 시작하지 않고 Edge 156에서 실제 `file:` URL로 실행함. 8개 검증 묶음 통과, 런타임 오류와 HTTP 및 WebSocket 요청 0건임.
- 브라우저 저장값의 재실행 복원, 실제 설정 JSON의 파일 선택 입력과 JSON 다운로드, 키패드 성공과 오답 및 시간 초과, 고정 노트 시각과 결과 다운로드를 확인함. 테스트 중 실제 설정 JSON은 변경하지 않음.
- 1920×1080, 1365×768과 폭 390 화면에서 가로 넘침 없음 확인함. [직접 실행 화면](<검증/09 서버 없는 직접 실행.png>)과 [직접 실행 즉시 판정](<검증/10 직접 실행 즉시 판정.png>)을 직접 열어 이미지와 두 설정 및 즉시 판정과 잔여 시간을 확인함.
- 결과는 [서버 없는 검증 결과.json](<검증/서버 없는 검증 결과.json>)임. 기존 Python 서버 종료 후 해당 서버 프로세스와 18764 리스너가 남아 있지 않음을 확인함. 이전 서버 방식의 검증을 이번 직접 실행의 검증으로 대신하지 않음.

## 5.2 미확인 범위

- 연결 파일 자동 쓰기 로직은 테스트 핸들로 확인함. 이번 헤드리스 환경에서는 `file:` 문맥의 오리진 전용 파일 시스템(OPFS)이 제한됐고 컴퓨터 제어 도구도 연결 오류로 사용할 수 없었음. 실제 OS 파일 선택과 권한 승인 및 실제 핸들의 재실행 복원은 미검증임. 일반 JSON 가져오기와 다운로드는 실제 파일로 검증함.
- 실제 음원 재생 및 음악 시각 동기화, 카메라 모션 입력과 체험자의 적정 시간값은 미검증임. 화면 전환은 브라우저 프레임 주기에 따르며 물리적인 디스플레이 지연은 측정하지 않음.
- 사용자 검토 전 상태임. 프로토타입의 시간값과 결과를 정식 기획 기준으로 자동 반영하지 않음.
