# 1 용도와 관리 위치

- 공통 UI(User Interface, 사용자 인터페이스) 텍스트와 개별 콘텐츠의 이름 풀을 한 폴더에서 관리함. 파일명으로 용도 구분함.
- 현재 위치: `90_작업 공간/번역 검수`. 검수할 JSON(JavaScript Object Notation, 데이터 교환 형식)과 이 README를 함께 보관함.
- 확정본 보관 위치: `04_자산 영역/00_Localization`. 확정 반영 시 JSON과 설명 문서의 경로를 함께 갱신함.
- 번역 판단 기준: [번역 검수 규칙](<../../00_시스템/01_규정/번역 검수 규칙.md>). 대소문자, 아포스트로피, 용어와 이름 표기의 기준은 해당 규칙에서 관리함.

# 2 파일과 구조

| 파일 | 용도 | 실제 구조 | 항목 수 |
|---|---|---|---|
| [localization.json](<localization.json>) | 여러 콘텐츠가 함께 사용하는 버튼, 라벨, 팝업과 안내 문구 | 문자열 키를 가진 `key → { ko, en }` 평면 맵 | 112개 |
| [character_name_pool.json](<character_name_pool.json>) | 개별 콘텐츠에서 사용하는 한국어 이름과 대응 영문명의 이름 풀 | 문자열 인덱스를 가진 `인덱스 → { ko, en }` 평면 맵 | 20개 |

## 2.1 localization.json

- `ko`는 한국어 원문, `en`은 대응 영어 텍스트임.
- 현재 키 접두 범위: `1_`, `3_`, `5_`, `13_`, `14_`.
- 플레이스홀더: `{0}`, `{1}` 형식으로 실행 중의 값을 치환하는 자리 표시임.

## 2.2 character_name_pool.json

- 현재 인덱스 범위: 문자열 `"0"`부터 `"19"`까지임.
- `ko`는 한국어 이름, `en`은 대응 창작 영문명임. 이름의 번역 기준은 [번역 검수 규칙: 이름 풀은 창작 영문명](<../../00_시스템/01_규정/번역 검수 규칙.md#43-이름-풀은-창작-영문명>)에 따름.

# 3 입력 자료와 관리 방식

- 사용자가 제공한 기존 클라이언트 데이터 README의 파일 안내를 현재 폴더 구성에 맞춰 정리함. 실제 파일 목록과 구조는 이 폴더의 JSON 2개에서 확인함.
- 확인된 정식 제작 근거 문서가 없어 `sources: []` 유지함.
- 번역값과 키는 JSON 파일에서 관리함. 이 README에는 파일 용도와 구조를 설명하며 전체 값을 중복 나열하지 않음.
- 검수와 반영 절차는 [번역 검수 규칙: 반영 절차](<../../00_시스템/01_규정/번역 검수 규칙.md#13-반영-절차>)에 따름.

# 4 확인 범위

- JSON 2개의 구문, 최상위 평면 맵, 모든 항목의 `ko`, `en` 필드와 문자열 값, 항목 수 확인함.
- `_meta` 필드 없이 이름 풀 20개와 UI 텍스트 112개를 관리하는 현재 구조 확인함.
- 이번 정리는 파일 안내와 구조 확인에 한정함. 실제 번역 정확성과 표기 기준의 충족 여부는 번역 검수 시 확인함.
