# 1 기본 형식

- 문서는 UTF-8 Markdown으로 저장한다.
- `AGENTS.md`를 포함한 관리·지식·리소스 설명·로그 문서는 파일 최상단에 YAML 프론트매터를 둔다.
- 문서 제목은 프론트매터의 `title`에서 관리한다. H1은 문서 제목이 아니라 본문의 대분류로 사용한다.
- 아래의 본문 항목은 기본 구성이다. 문서 목적에 맞게 항목명과 상세 수준을 조정할 수 있다.
- 예시의 `문서 제목`, `문서명`, `작성일` 등은 실제 값으로 바꾼다. 확인된 출처가 없다면 `sources: []`로 두고 이유를 본문에 설명한다.

# 2 문서 제목과 파일명

- `title`은 문서의 제목, 파일명은 파일을 저장·식별하는 이름이다. 둘은 별개이며 `title`을 수정해도 파일명은 자동으로 변경되지 않는다.
- 일반 지식 문서와 리소스 설명 문서는 기본적으로 파일명의 확장자를 제외한 이름과 `title`을 일치시킨다. 예: `전투 시스템.md`의 `title`은 `전투 시스템`.
- 고정 이름을 사용하는 운영 문서와 월별 로그는 예외로 한다. 예: `AGENTS.md`의 `title`은 `위키 작업 지침`, `2026-10.md`의 `title`은 `2026년 10월 작업 로그`.
- 기존 운영 문서의 파일명은 유지한다. 파일명을 변경하는 경우 해당 파일을 가리키는 링크도 함께 갱신한다.
- 문서 제목을 본문 H1에 다시 작성하지 않고, 첫 대분류부터 본문을 시작한다.

# 3 헤더 넘버링

## 3.1 번호 형식

| 레벨 | 번호 형식 | Markdown 예시 |
|---|---|---|
| H1 | `1`, `2`, `3` | `# 1 대분류` |
| H2 | `1.1`, `1.2`, `1.3` | `## 1.1 중분류` |
| H3 | `1.1.1`, `1.1.2`, `1.1.3` | `### 1.1.1 소분류` |
| H4 | `1)`, `2)`, `3)` | `#### 1) 세부 항목` |
| H5 | `(1)`, `(2)`, `(3)` | `##### (1) 상세 항목` |

- 번호와 헤더 제목 사이에 공백 하나를 둔다.
- 헤더 레벨을 건너뛰지 않고, 정보의 계층에 맞게 사용한다.
- 헤더 번호와 본문의 번호 목록은 서로 독립적으로 관리한다.

## 3.2 번호 초기화와 갱신

- H1은 문서의 본문 순서대로 `1`부터 연속 부여한다.
- H2는 H1 번호에 해당 H1 안의 순번을 붙인다. H1이 바뀌면 마지막 순번을 `1`부터 다시 시작한다.
- H3는 H2 번호에 해당 H2 안의 순번을 붙인다. H2가 바뀌면 마지막 순번을 `1`부터 다시 시작한다.
- H4는 각 H3 안에서 `1)`부터, H5는 각 H4 안에서 `(1)`부터 다시 시작한다.
- 절을 추가·삭제·이동하면 해당 문서의 번호를 갱신한다. 변경된 헤더를 가리키는 링크도 점검한다.
- 특정 절을 참조할 때 문서명과 헤더 제목을 함께 표시한다. 세부 참조 방식은 [문서 작성 규칙](Writing_Rules.md)의 `근거와 판단의 표시` 절을 따른다.

# 4 프론트매터

| 필드 | 적용 | 값과 의미 |
|---|---|---|
| `title` | 공통 필수 | 문서 제목 문자열 |
| `type` | 공통 필수 | `system`, `reference`, `synthesis`, `article`, `asset`, `log` 중 하나 |
| `created` | 공통 필수 | 최초 작성일. `"YYYY-MM-DD"` 문자열 |
| `updated` | 공통 필수 | 마지막 내용 수정일. `"YYYY-MM-DD"` 문자열 |
| `status` | 지식·리소스 설명 문서 필수 | `draft`, `review`, `confirmed`, `superseded`, `rejected` 중 하나 |
| `sources` | 지식·리소스 설명 문서 필수 | 실제 사용한 근거 문서·원자료 목록 |
| `source_check` | References 필수 | `unverified`, `partial`, `verified`, `not_applicable` 중 하나 |
| `reviewed` | 확정 Article·Asset 필수 | 마지막 검토일. `"YYYY-MM-DD"` 문자열 |
| `review_note` | 확정 Article·Asset 필수 | 실제 수행한 검토와 남은 한계의 간단한 기록 |
| `target_folder` | Workspace의 지식·리소스 설명 문서 필수 | 최종 목적 폴더. `01_References`, `02_Syntheses`, `03_Articles`, `04_Assets` 중 하나 |
| `asset_files` | 리소스 설명 문서 필수 | 해당 설명 문서가 관리하는 리소스 경로 목록 |

- `sources`의 내부 문서 링크는 위키 루트 기준 Obsidian 링크 문자열로 기록한다. 예: `"[[01_References/문서명]]"`.
- 외부 원자료는 URL 또는 식별 가능한 서지 정보를 기록한다. 페이지·절·시점 등 세부 근거 위치는 본문에 기록한다.
- `sources`에는 운영 규정이나 작업 로그를 넣지 않는다. `target_folder`의 허용 범위는 루트의 [AGENTS.md](../../AGENTS.md)를 따른다.
- `status`는 문서의 작업·채택 상태를 뜻한다. `confirmed`는 모든 출처의 내용이 사실로 입증되었다는 뜻이 아니다.
- `source_check`는 원자료 대조 상태를 뜻한다. `verified`도 원자료 자체의 완전한 진실성을 보증하지 않는다. 확인 방법과 범위는 본문에 기록한다.
- 원자료를 대조하지 않았으면 `unverified`, 일부만 대조했으면 `partial`, 해당 범위의 대조를 마쳤으면 `verified`로 기록한다. 외부 사실 검증의 대상이 아닌 사용자 요구사항 등은 사유와 함께 `not_applicable`로 기록할 수 있다.
- `superseded`는 다른 내용으로 대체된 문서, `rejected`는 채택하지 않은 작업물이다. 현재 확정 내용과 섞이지 않도록 대체 위치나 사유를 본문에 표시한다.

# 5 References

```yaml
---
title: "문서 제목"
type: reference
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
status: draft
sources: []
source_check: unverified
---
```

- 기본 본문: `자료 개요` → `출처·작성 방식` → `내용` → `확인 범위·미확인 사항`.
- 출처·작성 방식에 외부 자료, 사용자 작성, LLM 작성 등의 경위를 명시한다.
- LLM이 작성한 설명은 그 자체로 외부 사실의 입증 자료가 되지 않는다. 근거가 있는 내용은 원자료를 연결하고, 나머지는 미확인으로 표시한다.

# 6 Syntheses

```yaml
---
title: "문서 제목"
type: synthesis
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
status: draft
sources:
  - "[[01_References/문서명]]"
---
```

- 기본 본문: `목적·범위` → `종합·비교·분석` → `해석·추론` → `한계·추가 확인 사항`.
- 분석에 사용한 자료와 주장별 근거 위치를 기록한다.

# 7 Articles

```yaml
---
title: "문서 제목"
type: article
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
status: draft
sources:
  - "[[01_References/문서명]]"
  - "[[02_Syntheses/문서명]]"
---
```

- 기본 본문: `목적·범위` → `본문` → `한계·미정 사항` → `근거`.
- 실제로 사용한 출처만 남긴다. 기존 확정 Article을 사용한 경우 해당 링크도 기록한다.
- 확정 시 `reviewed`와 `review_note`를 추가한다. 이후 내용을 수정하면 검토 기록도 갱신한다.

# 8 Assets

- 이미지·영상·음원 파일은 프론트매터를 가질 수 없으므로 Markdown 설명 문서를 함께 둔다. 예: `장면.png`와 `장면.md`.
- 리소스 설명 문서와 실제 리소스를 함께 관리한다.

```yaml
---
title: "리소스 제목"
type: asset
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
status: draft
sources: []
asset_files:
  - "04_Assets/파일명.png"
---
```

- 기본 본문: `용도` → `파일·규격` → `입력 자료·생성 또는 편집 방법` → `검토 결과·한계`.
- 생성 시 실제 사용한 프롬프트나 설정이 있다면 재현에 필요한 범위에서 기록한다.
- `asset_files`는 위키 루트 기준 경로로 기록한다. Workspace 작업 중에는 현재 경로를 기록하고, 확정 반영할 때 갱신한다.
- 확정 시 `reviewed`와 `review_note`를 추가한다.

# 9 System과 Logs

- System 문서는 공통 필드 4개와 실제 운영 내용을 기록한다.
- 월별 로그는 `type: log`로 기록한다. 최신 내용의 삽입 절차는 [Workflow.md](Workflow.md)를 따른다.
- 로그 한 항목의 기본 형식:

```markdown
# 1 YYYY-MM-DD HH:mm — 작업명

- 대상: 변경한 문서 또는 파일 경로.
- 작업: 생성·수정·검증·확정 등 실제 수행 내용.
- 이유: 작업 또는 변경의 근거.
- 검증: 실제 확인한 사항과 결과.
- 결과: 반영 위치, 현재 상태, 남은 작업.
```

- 시간은 별도 지정이 없으면 한국 표준시(Asia/Seoul)로 기록한다.

# 10 Workspace와 파일 이동

- Workspace 문서는 문서 종류에 맞는 프론트매터에 `target_folder`를 추가한다.
- 정식 폴더에 반영할 때 `target_folder`를 제거하고, 파일 경로와 링크를 점검한다.
- 제목과 파일명은 내용을 식별할 수 있도록 작성한다. 기존 문서와 혼동되는 이름을 피한다.
