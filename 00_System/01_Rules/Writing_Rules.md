# 1 적용 범위

- 위키의 설명 문서와 리소스 설명 문서에 적용한다.
- 문서 종류별 형식은 [Document_Format.md](Document_Format.md)를 따른다.
- 사용자가 특정 문서의 표현·구성을 지정한 경우 해당 요청을 적용한다.

# 2 작성 순서

1. 문서의 목적, 독자, 범위를 정한다.
2. 정보를 수집하고 출처를 확인한다.
3. 정보를 주제·기능·단계 등 적절한 기준으로 분류한다.
4. 분류한 정보의 관계를 정리하고 제목 계층을 구성한다.
5. 이해에 필요한 순서를 정한 후 작성한다.
6. 중복, 누락, 근거와 표현의 일치를 검토한다.

# 3 서술 방식

- 개조식을 기본으로 한다.
- 한 항목에는 하나의 핵심 내용 또는 밀접하게 연결된 내용을 담는다.
- 문장은 짧고 명확하게 작성한다. 문맥상 필요한 주체·조건·범위를 생략하지 않는다.
- 동일한 계층의 항목은 표현과 상세 수준을 맞춘다.
- 문서 내 같은 개념에는 같은 용어를 사용한다. 약어는 처음 사용할 때 풀어서 설명한다.
- 인과관계나 긴 설명에 문단이 더 적합하면 짧은 문단을 사용한다.

# 4 정보 배열

- 개요·정의에서 세부 내용으로 진행한다.
- 전제와 조건은 해당 내용을 이해하는 데 필요한 위치에 먼저 제시한다.
- 절차는 수행 순서, 사건은 시간 순서, 비교는 동일한 비교 항목 순서로 정리한다.
- 같은 분류에 속하는 정보를 모으고, 서로 다른 분류 기준을 같은 계층에 섞지 않는다.
- 병렬 비교는 표, 수행 순서는 번호 목록, 독립적인 항목은 불릿 목록을 사용한다.
- 공통 정보는 한 번 설명하고, 관련 항목에서는 해당 위치를 참조한다.
- 정보 분류와 각 헤더의 상하 관계가 내용상 적절한지는 작성자와 Codex가 검토한다. 번호 계산 도구의 검사 통과를 내용 구조의 검토 완료로 취급하지 않는다.

# 5 근거와 판단의 표시

- 주요 주장 옆 또는 해당 절에 출처를 표시한다. 문서 끝의 출처 목록만으로 어느 주장을 뒷받침하는지 불명확하게 만들지 않는다.
- 문서의 특정 절을 참조할 때는 문서명과 헤더 제목을 함께 표시한다. 예: `전투 시스템 — 피해 판정`. 절 번호만으로 위치를 가리키지 않는다.
- 실제 연결은 대상 파일 경로와 해당 헤더를 사용한다. 파일명과 `title`이 다른 경우에도 표시하는 문서명은 `title`을 기준으로 한다.
- 원문이 주장하는 내용과 작성자의 해석을 구분한다.
- 출처에서 직접 확인되지 않는 추론은 `해석` 또는 `추론`임을 밝힌다.
- 확인되지 않은 내용은 `미확인`, 설계가 결정되지 않은 내용은 `미정`으로 표시한다.
- 상충하는 자료는 차이와 확인 범위를 기록한다. 근거 없이 하나를 확정하지 않는다.
- 수치·날짜·단위·적용 조건은 원자료와 대조한다.

# 6 최종 정리

- 문서 목적과 무관한 내용을 제거한다.
- 현재 내용과 미정 사항을 구분한다. 대체·폐기된 이전안을 기록할 때는 상태를 명시한다.
- 프론트매터와 본문의 상태가 일치하는지 확인한다.
- 본문 헤더 번호는 [문서 형식](Document_Format.md)의 `헤더 넘버링` 절에 따라 자동 계산·검증한다. 월별 로그는 번호 적용에서 제외한다.
- 변경 후 작업 기록은 [Workflow.md](Workflow.md)에 따라 남긴다.
