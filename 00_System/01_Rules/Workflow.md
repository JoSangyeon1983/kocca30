# 1 작업 정의

- 요청의 목적, 결과물 종류, 최종 목적 폴더를 확인한다.
- 작성·수정·확정·반영 중 부여된 작업 범위를 확인한다.
- 기존 문서를 수정하는 경우 실제 현재 내용을 읽고, 현재안과 대체·폐기안을 구분한다.
- 출처 범위는 루트의 [AGENTS.md](../../AGENTS.md)를 따른다.

# 2 자료 선정

- 최종 목적 폴더에서 허용하는 출처를 선정한다.
- 색인으로 문서를 찾되, 근거로 사용할 문서의 실제 내용을 읽는다.
- 출처가 없거나 확인이 불가능한 내용은 미확인으로 기록한다.
- 기존 Article을 참조할 때는 확정 상태와 현재 유효한 내용을 확인한다.

# 3 작성·수정

- 새 문서와 실질적인 내용 수정은 `90_Workspace`에서 작업한다.
- [Writing_Rules.md](Writing_Rules.md)에 따라 분류·구조화한 후 작성한다.
- [Document_Format.md](Document_Format.md)에 따라 프론트매터와 본문을 구성한다.
- 기존 확정 문서의 수정 초안은 원본을 보존한 상태로 만든다.
- 작성자는 정보 분류와 헤더 계층을 먼저 정한다. 작성 중에는 헤더 번호를 생략할 수 있다.
- 작성·수정 후 아래의 번호 도구를 실행하고, 검증할 준비가 되면 `status: review`로 변경한다.

## 3.1 헤더 번호 도구 실행

- 실행 파일: `00_System/03_Tools/heading_numbers.py`.
- 실행 환경: Python 3.9 이상. 별도 패키지 설치 없이 실행한다.
- 아래 명령은 위키 최상위 폴더에서 실행한다. `문서명.md`는 실제 대상 경로로 바꾼다.
- 첫 번호 부여는 제목 전체를 보존하고 번호를 앞에 붙인다.

```powershell
python 00_System/03_Tools/heading_numbers.py apply "90_Workspace/문서명.md" --input unnumbered
```

- 이미 번호가 있는 문서의 수정·재정렬 후에는 기존 번호 재계산을 사용한다. 이 모드는 제목 앞의 숫자 표기를 기존 번호로 취급한다.

```powershell
python 00_System/03_Tools/heading_numbers.py apply "90_Workspace/문서명.md" --input numbered
```

- `unnumbered`는 처음 번호를 부여할 때만 사용한다. 이미 번호가 있는 파일에 반복 실행하면 중복 번호가 붙을 수 있다.
- 기존 문서에 `2026 계획`처럼 번호와 혼동되는 새 제목을 추가했다면 `--literal-line 12`처럼 실제 행 번호를 지정하여 해당 제목 전체를 보존한다. 이 옵션은 단일 파일의 재계산에서만 사용하며, 다음 재계산에서는 제거한다.
- 적용 후 해당 문서의 번호와 헤더 링크를 검사한다.

```powershell
python 00_System/03_Tools/heading_numbers.py check "90_Workspace/문서명.md"
```

- `check`에서 경로를 생략하면 위키 전체를 읽기 전용으로 검사한다. `apply`는 명시한 파일만 수정한다.
- 다른 폴더에서 실행할 경우 `--root "위키 최상위 폴더 경로"`를 추가한다.
- 적용 중 계층 오류나 변경될 헤더를 가리키는 링크 오류가 발견되면 파일을 수정하지 않는다. 작성자 또는 Codex가 계층과 링크를 검토한 뒤 재실행한다.
- 링크 오류는 적용 후의 헤더를 기준으로 판정한다. 보고된 새 헤더 제목으로 관련 링크를 먼저 수정하고 적용을 재실행한다. 링크는 도구가 임의로 바꾸지 않는다.
- 인식 범위는 독립된 `#` 형식 헤더와 일반적인 인라인 Markdown·Obsidian 헤더 링크다. 밑줄형 헤더는 정리 대상으로 보고하며, 참조식 링크나 별칭만을 이용한 연결 등의 추가 문법은 별도로 검토한다.
- 종료 코드: `0`은 통과, `1`은 번호·계층·링크 검사 오류, `2`는 실행 조건 또는 파일 처리 오류다. 월별 로그의 번호 검사 제외는 `SKIP_LOG`로 표시한다.
- 도구 수정 후에는 동봉한 검증 코드를 실행한다.

```powershell
python 00_System/03_Tools/test_heading_numbers.py
```

# 4 검증

- 다음 항목을 확인하고 실제 결과를 기록한다.
  - 출처가 최종 목적 폴더의 허용 범위에 있는가.
  - 주요 주장과 근거가 대응하며, 실제 근거 내용을 확인했는가.
  - 원자료의 내용과 해석·추론·미확인 사항이 구분되어 있는가.
  - 미정·대체·폐기된 내용이 현재 확정 내용으로 섞이지 않았는가.
  - 분류·설명 순서·용어가 일관되며, 누락과 불필요한 중복이 없는가.
  - 프론트매터의 필드·값, 날짜, 링크와 파일 경로가 맞는가.
  - 정보 분류와 헤더 계층의 의미가 적절한가. 이 항목은 작성자와 Codex가 검토한다.
  - 본문 문서의 번호 계산·형식 검증 도구가 통과했는가. 월별 로그는 번호 적용에서 제외한다.
  - 특정 절의 참조에 문서명과 헤더 제목이 함께 표시되어 있는가.
  - 리소스라면 파일이 열리며 요청한 내용·규격에 부합하는가.
- 검증은 초안에서 사용한 같은 자료의 요약을 다시 읽는 데 그치지 않고, 중요한 주장과 실제 근거를 대조한다.
- 검증 중 문제가 발견되면 수정한 부분을 다시 확인한다. 확인하지 않은 항목은 검증 완료로 기록하지 않는다.

# 5 확정·반영

- Articles와 Assets는 검토를 마치고 확정·반영이 요청 범위에 포함된 경우 정식 폴더에 반영한다.
- 사용자가 초안 또는 검토안을 요청한 경우 Workspace에 유지한다. 별도 승인이 실제로 필요한 경우에만 확인을 요청한다.
- References와 Syntheses도 출처 기록과 형식을 점검한 뒤 정식 폴더에 반영한다. 남은 불확실성은 보존한다.
- 확정한 문서는 `status: confirmed`로 기록한다. 확정 Article·Asset에는 `reviewed`, `review_note`를 기록한다.
- 초안의 `target_folder`를 제거하고, 이동 후 링크·리소스 경로를 갱신한다.
- 기존 문서를 갱신하면 `created`는 유지하고 `updated`와 검토 기록을 갱신한다.
- 대체된 내용을 별도 보존하는 경우 `superseded`, 채택하지 않은 작업물은 `rejected`로 표시하고 사유를 남긴다.
- 관련 색인에 정식 문서 링크와 한 줄 설명을 추가하거나 수정한다.

# 6 월별 로그

- 로그 경로: `00_System/02_Logs/YYYY-MM.md`.
- 위키 파일에 실제 변경이 발생한 작업만 월별 로그에 기록한다.
- 하나의 작업에서 여러 파일을 변경하면 한 항목으로 묶는다.
- 로그 기록 자체를 별도 작업으로 다시 기록하지 않는다.
- 기록 대상 작업을 마칠 때 작업한 달의 문서에 기록한다. 해당 월의 문서가 없으면 만든다.
- 월과 기록 시각은 별도 지정이 없으면 한국 표준시(Asia/Seoul)를 기준으로 한다.
- 로그의 제목은 프론트매터 `title`에서 관리하고, 각 작업 항목은 H1로 작성한다.
- 월별 로그의 H1~H5 헤더에는 번호를 붙이지 않는다. 각 항목의 날짜·시각·작업명이 식별 기준이다.
- 새 기록은 프론트매터 다음, 기존 기록보다 위에 삽입한다.
- 새 항목을 추가할 때 기존 항목의 번호를 다시 매기는 작업은 수행하지 않는다.
- 항목은 작업 시각의 내림차순으로 정렬한다. 같은 날짜도 최신 시각이 위에 온다.
- 기록 시각은 실제 작업 시각을 사용한다. 시간이 불명확하면 날짜만 기록하고 임의의 시각을 만들지 않는다.
- 로그에 작업 대상·수행 내용·변경 이유·검증 결과·현재 상태를 기록한다. 양식은 [Document_Format.md](Document_Format.md)를 따른다.
- 로그는 운영 이력이다. 프로젝트 지식의 근거는 실제 정식 출처 문서에서 확인한다.
- 월별 로그 파일을 새로 만들면 색인에 링크를 추가한다.
